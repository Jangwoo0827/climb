# 홀드 분류 → 그립 → 자세 흐름 분석 (2026-10-04)

코드를 고치기 전에 현재 구조, 데이터, 모델, 문제를 정리한 문서예요.

## 1. 현재 구조

```
사진 → detect.js(색 기반 홀드 검출, 홀드별 tight box) → holdModel.js(TF.js, 홀드 crop 1장씩 분류)
     → App.jsx typedHolds(종류 결정) → route.js(경로, 종류별 난이도 감점) → stickman.js(자세)
     → hand.js(종류별 손 모양 그림)
```

- **종류 결정 순서:** `App.jsx` `typedHolds`에서 아래 순서로 정해요.
  1. 직접 고친 종류
  2. 모양으로 판정한 볼륨(`h.volume`)
  3. AI 결과(확신도 0.5 이상)
  4. 크기·모양 규칙 `estimateHoldType`
- **AI가 '볼륨'이라고 할 때:** 볼륨을 뺀 나머지 종류 중 가장 높은 것을 써요(볼륨은 모양으로만 정함).
- **종류를 쓰는 곳:**
  - `route.js`: 종류별 난이도 감점(`HOLD_TYPES[type].penalty`), 동작 이름(볼륨 → 맨틀).
  - `stickman.js`: 볼륨인지만 봐요(발 자리 보너스).
  - `hand.js`: 손 모양을 정해요.

## 4. 실제 벽 사진 4장에서 앱 흐름 그대로 측정 (브라우저에서 `detectHolds` → `classifyHolds`)

검출기가 만든 실제 홀드 상자로 배포 모델을 돌렸어요(사진 4장, 홀드 362개).

| 사진 | 홀드 | AI가 volume | volume 확신도 중앙값 | 최종 jug | 최종 crimp | 최종 sloper |
|---|---|---|---|---|---|---|
| climbing-wall | 84 | 52 (62%) | 0.97 | 4 | 42 | 22 |
| 4-1 | 91 | 44 (48%) | 0.92 | 4 | 34 | 18 |
| 119720094.2 | 78 | 42 (54%) | 0.95 | 2 | 43 | 23 |
| image.webp | 109 | 72 (66%) | 0.95 | 0 | 70 | 28 |

- **볼륨 쏠림:** AI가 **보통 크기 홀드의 절반 이상을 확신도 95%로 '볼륨'**이라고 해요. 볼륨으로 답한 홀드의 상자 넓이 중앙값은 나머지보다 1.4~2.7배 커서 크기 영향이 있어요. 다만 흰 벽 사진(image.webp)에서는 작은 홀드도 볼륨이라 해서, 배경(흰·회색 벽)도 함께 배운 것으로 보여요. 볼륨 학습 사진 25장이 흰 배경 위의 큰 물체여서 생긴 편향으로 추정해요(확인 필요).
- **저그가 사라지는 경로:** 큰 홀드는 실제로는 대부분 저그예요. 그런데 AI는 볼륨이라 하고, 앱은 볼륨을 빼고 두 번째 종류를 골라요. 이 두 번째가 크림프·슬로퍼라서 **저그가 거의 0개**가 돼요(362개 중 10개).

## 5. "모든 홀드를 같은 방식(저그처럼)으로 잡는" 원인

명세의 8번 항목을 끝까지 추적했어요.

| 확인 항목 | 결과 |
|---|---|
| 분류 실패 시 JUG fallback | `hand.js` `GRIPS[type] ?? GRIPS.jug`: 종류가 없을 때만 해당. 직접 추가한 홀드 기본값과 발 전용 홀드도 'jug' |
| confidence threshold | 0.5 미만이면 크기 규칙(`estimateHoldType`)을 씀. jug 고정 아님 |
| index → class name 매핑 | `metadata.json` labels 순서대로 사용, 맞음(실험 평가에서 확인) |
| 확률 보존 | `predict`가 `probs`를 반환하지만 `typedHolds`에서 최고 1개만 쓰고 나머지 확률은 버려요 |
| 자세 코드 하드코딩 | **자세(`stickman.js`)는 홀드 종류를 전혀 안 써요(볼륨만 예외).** 언더클링도, 사이드풀도, 슬로퍼도 몸 위치는 저그와 똑같이 계산돼요 |
| grip 함수 연결 | 손 모양(`hand.js`)은 종류별로 다르게 연결돼 있어요(오늘 추가) |

정리하면 원인은 세 가지예요.

1. **분류:** 모델이 큰 홀드를 볼륨으로 몰고, 앱의 볼륨 대체 규칙이 저그를 지워요.
2. **연결:** 확률을 버리고 1등 종류 하나만 써요.
3. **자세:** 자세 계산이 종류를 무시해서, 어떤 홀드든 "아래로 당기는 저그 자세"가 돼요. 사용자가 본 "다 저그처럼 잡는다"의 직접 원인이에요.

## 6. 개선 계획(단계별)

1. 측정 기준 고정: 실제 사진 test(Capstone 55장 + 위 사진 4장에 라벨을 붙인 세트)로 baseline 지표를 만들어요.
2. 볼륨 쏠림 수정:
   - 볼륨은 모양 판정(`detectVolumes`)으로만 정하고, 분류기에서는 볼륨 클래스를 빼거나 학습 데이터를 고쳐요(볼륨 사진의 크기·배경이 실제 홀드 crop과 달라 크기를 배운 것으로 보여요).
   - "볼륨이면 2등" 규칙 대신 확률에서 볼륨을 빼고 다시 정규화한 분포 전체를 넘겨요.
3. 확률 보존: `typedHolds`에 `probs`를 유지하고, 경로 난이도 감점과 손 모양을 확률 가중으로 정해요. 애매하면 표시도 "크림프 61% / 핀치 21%"처럼 해요.
4. 자세가 종류를 쓰게:
   - 언더클링: 몸이 홀드보다 위.
   - 사이드풀: 홀드 반대쪽으로 기울기.
   - 슬로퍼: 몸을 홀드 아래로 낮춤.
   - 핀치·크림프: 팔을 덜 펴도 됨.
5. PyTorch 분류기: MobileNetV3/EfficientNet-B0을 fine-tuning하고 class weighting과 augmentation을 써요. 실험 002와 같은 test로 비교해요. 이 PC에는 PyTorch가 없고 GPU도 없어서 CPU 학습이에요(이미지 수천 장 규모라 가능). 앱 연결은 ONNX → onnxruntime-web 또는 TF.js 변환이 필요해요.
6. 실제 벽 사진 추론과 그립·자세 반영을 검증해요.
